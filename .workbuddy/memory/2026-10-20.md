## UGC/PGC「部分加载失败」根因诊断
- 现象：进入 UGC（如 Kichiku 鬼畜）等分区，首次/翻页时部分列表弹"加载 X 数据失败"，logcat 出现 `I UgvViewModel[<类型>]: load more <类型> data failed: IllegalStateException: 暂时没有更多内容了`(乱码为 UTF-8 中文被 PowerShell GBK 误显)。
- 根因链：B站 `/x/web-interface/region/feed/rcmd` 在翻页到底/某些分区返回 `code!=0` + message「暂时没有更多内容了」→ `bili-api/.../http/entity/BiliResponse.kt:22` 的 `getResponseData()` 对 `code!=0`（非 -101/-352）统一 `throw IllegalStateException(message)` → `UgcViewModel.loadMore()` / `ZoneDetailViewModel.loadUgcRegionData()` 的 `runCatching.onFailure` 把它当作"加载失败"弹 toast。
- 本质：不是真错误，是"已到底/无更多"的正常终态被接口以非0 code 返回、被代码误判为加载失败 → 表现为"部分加载失败"。
- 失败日志去向：经 `fInfo` → (1) logcat INFO 级，tag=`UgvViewModel[类型]`(拼错少c)/`PgcViewModel[类型]`；(2) Firebase.crashlytics.log 面包屑(仅接入 google-services 时)；(3) 不自动落盘(仅崩溃/手动 logLogcat 才写 crash_logs/)。
- 修复方向（未执行，待用户确认）：在 UgcRepository.getRegionFeedRcmd 或 UgcViewModel 层把"没有更多"终态与真错误区分——message 含「没有更多内容」时设 hasMore=false 且不弹 toast；或 repository 返回空结果而非抛。注意 message 中文匹配脆弱，优先用接口返回的"是否到底"语义。
