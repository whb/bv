## UGC/PGC「部分加载失败」根因诊断
- 现象：进入 UGC（如 Kichiku 鬼畜）等分区，首次/翻页时部分列表弹"加载 X 数据失败"，logcat 出现 `I UgvViewModel[<类型>]: load more <类型> data failed: IllegalStateException: 暂时没有更多内容了`(乱码为 UTF-8 中文被 PowerShell GBK 误显)。
- 根因链：B站 `/x/web-interface/region/feed/rcmd` 在翻页到底/某些分区返回 `code!=0` + message「暂时没有更多内容了」→ `bili-api/.../http/entity/BiliResponse.kt:22` 的 `getResponseData()` 对 `code!=0`（非 -101/-352）统一 `throw IllegalStateException(message)` → `UgcViewModel.loadMore()` / `ZoneDetailViewModel.loadUgcRegionData()` 的 `runCatching.onFailure` 把它当作"加载失败"弹 toast。
- 本质：不是真错误，是"已到底/无更多"的正常终态被接口以非0 code 返回、被代码误判为加载失败 → 表现为"部分加载失败"。
- 失败日志去向：经 `fInfo` → (1) logcat INFO 级，tag=`UgvViewModel[类型]`(拼错少c)/`PgcViewModel[类型]`；(2) Firebase.crashlytics.log 面包屑(仅接入 google-services 时)；(3) 不自动落盘(仅崩溃/手动 logLogcat 才写 crash_logs/)。
- 修复方向（未执行，待用户确认）：在 UgcRepository.getRegionFeedRcmd 或 UgcViewModel 层把"没有更多"终态与真错误区分——message 含「没有更多内容」时设 hasMore=false 且不弹 toast；或 repository 返回空结果而非抛。注意 message 中文匹配脆弱，优先用接口返回的"是否到底"语义。

## 鬼畜分区编号 vs 官方文档核对（"鬼畜查不到视频"排查）
- 用户疑心 `region/feed/rcmd` 的 `from_region` 分区号写错。实测 + 对比官方 v2 分区表：
  - 官方 bilibili-API-collect `video_zone_v2`：鬼畜主分区 `tid=1007, channelId=9, code=kichiku`；子分区 guide=2059/theatre=2060/manual_vocaloid=2061/mad=2062/other=2063。
  - 项目 `UgcTypeV2.kt`：`Kichiku(1007,"kichiku",9)` 及 5 个子分区**与官方逐字一致**。
  - 老的 `UgcType.kt` 用 `rid=119`（旧 rid 系统，鬼畜主分区 rid=119，子分区 22/26/126/216/127），与旧 rid 系统也一致；但 `getRegionDynamic` 等已 `@Deprecated`，当前 `region/feed/rcmd` 走 `tid`。
- **实测（WebFetch 直接打线上接口）**：
  - `from_region=1007&display_id=1&request_cnt=15&device=web&plat=30` → `code:0`，返回 15 条真实鬼畜视频 + banner 6 条 ✅
  - `from_region=119` → `code:-400 请求错误, data:null` ❌
  - 即 `tid=1007` 正确，`rid=119` 才是错的（反证项目用 tid 是对的）。
- **结论**：编号无误，鬼畜"查不到视频"不是分区号问题。真正原因更可能是：① B站服务端地域限制（本项目原为非大陆设计，从大陆网络访问 `region/feed/rcmd` 等可能被返回空/错误码，区别于已摘除的启动期 Cloudflare 大陆拦截）；② 设备网络连不上 api.bilibili.com；③ 翻页到底的"暂时没有更多内容了"误报（见上）。需抓 app 实际收到的 `code/message` 才能定位。`getResponseData()` 把非0 code 一律转异常，首次加载若拿到 -404/-412 等会被当作"失败"而非"地域限制"。
- 下一步建议：在 `loadUgcRegionData`/`getResponseData` 失败处把真实 code/message 透出到 toast/日志，区分「地域限制 / 到底 / 网络 / 真错误」。

## Splash 屏 logo —— 最终结论：放弃统一入口 SplashActivity，还原双 LAUNCHER
- 用户明确放弃「统一入口 SplashActivity」方案（v1~v5 在 API28 tv 模拟器上 logo 始终不显示均作废）。执行 `git checkout f7037cb4^ --`（回退 6 个文件）+ `git rm` 删除 SplashActivity.kt；`:app:tv/:app:mobile/:app:compileDefaultDebugKotlin` 全部 BUILD SUCCESSFUL。
- 关键发现：原始（统一入口前，父提交 f7037cb4^）的 `app/mobile/.../activities/MainActivity.kt` **已自带** `isTvDevice()` 判断——检测 `PackageManager.FEATURE_LEANBACK` 后 `startActivity` 转发到 `dev.oaktech.bv.tv.activities.MainActivity` 再 `finish()`。即"在 mobile 中判断 TV 加载 tv 代码"在原始结构里本就存在，还原即满足用户需求。
- 还原后入口结构：
  - tv `MainActivity`：LEANBACK_LAUNCHER + `Theme.BV.TV.Splash` + `installSplashScreen()`（logo 由 tv MainActivity 自身 splash 主题持有，API<31 上 compat splash 画在它自己窗口，正常显示——这正是统一入口前能显示 logo 的基线）。
  - mobile `MainActivity`：LAUNCHER + `Theme.BV.Mobile.Splash` + `installSplashScreen()`；检测到 TV 设备则转发 tv MainActivity。
  - `app/src/main/AndroidManifest.xml` 回到空清单；`app/build.gradle.kts` 移除 f7037cb4 加的 `implementation(project(":app:shared"))`。
- logo 资源：`app/shared/.../res/drawable/ic_launcher_foreground.xml`（粉色 B 站 vector），splash 主题 `windowSplashScreenAnimatedIcon` 指向它，配置未丢。
- 失败根因回顾：统一入口让空壳 SplashActivity 成为唯一 LAUNCHER，但它在 API<31 上窗口不绘制/被 MainActivity 立即盖住，compat splash 无机会显示；v1~v5 各种"撑住/延迟/Compose 兜底"都绕不开这个结构问题。

## 鬼畜/小剧场/vlog 三者「加载报错」精准定位 + 修复（已改文件，未编译验证）
- 用户排除地域限制：其它多数栏目正常，仅 鬼畜(1007)/小剧场(1021)/vlog(1029) 报错。
- 实测线上接口（WebFetch 直打 api.bilibili.com）逐页验证：

- 效果预期：鬼畜/vlog 首屏正常显示、不再弹"更多推荐失败"；小剧场 首屏若遇 62013 显示空但 hasMore 仍为 true，滚动触发第2页（实测可成功）→ 视频出现，且全程无错误 toast。

## TV 播放器「方向键下显示播放信息」功能恢复
