## UGC/PGC「部分加载失败」根因诊断
- 现象：进入 UGC（如 Kichiku 鬼畜）等分区，首次/翻页时部分列表弹"加载 X 数据失败"，logcat 出现 `I UgvViewModel[<类型>]: load more <类型> data failed: IllegalStateException: 暂时没有更多内容了`(乱码为 UTF-8 中文被 PowerShell GBK 误显)。
- 根因链：B站 `/x/web-interface/region/feed/rcmd` 在翻页到底/某些分区返回 `code!=0` + message「暂时没有更多内容了」→ `bili-api/.../http/entity/BiliResponse.kt:22` 的 `getResponseData()` 对 `code!=0`（非 -101/-352）统一 `throw IllegalStateException(message)` → `UgcViewModel.loadMore()` / `ZoneDetailViewModel.loadUgcRegionData()` 的 `runCatching.onFailure` 把它当作"加载失败"弹 toast。
- 本质：不是真错误，是"已到底/无更多"的正常终态被接口以非0 code 返回、被代码误判为加载失败 → 表现为"部分加载失败"。
- 失败日志去向：经 `fInfo` → (1) logcat INFO 级，tag=`UgvViewModel[类型]`(拼错少c)/`PgcViewModel[类型]`；(2) Firebase.crashlytics.log 面包屑(仅接入 google-services 时)；(3) 不自动落盘(仅崩溃/手动 logLogcat 才写 crash_logs/)。
- 修复方向（未执行，待用户确认）：在 UgcRepository.getRegionFeedRcmd 或 UgcViewModel 层把"没有更多"终态与真错误区分——message 含「没有更多内容」时设 hasMore=false 且不弹 toast；或 repository 返回空结果而非抛。注意 message 中文匹配脆弱，优先用接口返回的"是否到底"语义。

## 鬼畜分区编号 vs 官方文档核对（"鬼畜查不到视频"排查）
- 用户疑心 `region/feed/rcmd` 的 `from_region` 分区号写错。实测 + 对比官方 v2 分区表：
  - 官方 bilibili-API-collect `video_zone_v2`：鬼畜主分区 `tid=1007, channelId=9, code=kichiku`；子分区 guide=2059/theatre=2060/manual_vocaloid=2061/mad=2062/other=2063。
  - 项目 `UgcTypeV2.kt`：`Kichiku(1007,"kichiku",9)` 及 5 个子分区**与官方逐字一致**。
  - 老的 `UgcType.kt` 用 `rid=119`（旧 rid 系统，鬼畜主分区 rid=119，子分区 22/26/126/216/127），与旧 rid 系统也一致；但 `getRegionDynamic` 等已 `@Deprecated`，当前 `region/feed/rcmd` 走 `tid`。
- **实测（WebFetch 直接打线上接口）**：
  - `from_region=1007&display_id=1&request_cnt=15&device=web&plat=30` → `code:0`，返回 15 条真实鬼畜视频 + banner 6 条 ✅
  - `from_region=119` → `code:-400 请求错误, data:null` ❌
  - 即 `tid=1007` 正确，`rid=119` 才是错的（反证项目用 tid 是对的）。
- **结论**：编号无误，鬼畜"查不到视频"不是分区号问题。真正原因更可能是：① B站服务端地域限制（本项目原为非大陆设计，从大陆网络访问 `region/feed/rcmd` 等可能被返回空/错误码，区别于已摘除的启动期 Cloudflare 大陆拦截）；② 设备网络连不上 api.bilibili.com；③ 翻页到底的"暂时没有更多内容了"误报（见上）。需抓 app 实际收到的 `code/message` 才能定位。`getResponseData()` 把非0 code 一律转异常，首次加载若拿到 -404/-412 等会被当作"失败"而非"地域限制"。
- 下一步建议：在 `loadUgcRegionData`/`getResponseData` 失败处把真实 code/message 透出到 toast/日志，区分「地域限制 / 到底 / 网络 / 真错误」。

## Splash 屏 logo 不显示（统一入口后）——最终方案
- 现象：将 tv/mobile 入口统一到 `SplashActivity`（单一 dispatcher，LAUNCHER+LEANBACK_LAUNCHER）后，splash logo 不显示。
- 根因：开屏绑定在**持有 LAUNCHER 的 Activity** 上。SplashActivity 是唯一 LAUNCHER 且 install 了 splash、主题带 logo，但它是**空壳**（install→startActivity→finish，无 setContent、无 setKeepOnScreenCondition）。API < 31（用户 Android TV）上 compat 库把开屏画在 Activity 自己窗口里，一 finish 窗口连同 logo 消失；API ≥ 31 上系统 splash 也因立即 finish 来不及展示。而 tv/mobile MainActivity 有 setContent 却不是 LAUNCHER，冷启动不被认作开屏宿主。
- 最终方案（让 LAUNCHER 撑住开屏）：
  1. `SplashActivity.kt`：`installSplashScreen().setKeepOnScreenCondition { keepSplash }`（volatile 标志），注册 `Application.ActivityLifecycleCallbacks`，`startActivity(MainActivity)` 后**不 finish**；当目标 MainActivity `onActivityResumed` 时置 `keepSplash=false` 并 `finish()`，`onDestroy` 反注册回调。
  2. tv/mobile `MainActivity.kt`：移除 `installSplashScreen()` 调用与 import（不再持有开屏）。
  3. tv/mobile `AndroidManifest.xml`：MainActivity 主题从 `Theme.BV.TV.Splash`/`Theme.BV.Mobile.Splash` 改回普通 `Theme.BV.TV`/`Theme.BV.Mobile`。
  4. `app/src/main/AndroidManifest.xml`：SplashActivity 保持 `Theme.BV.Splash`（含 `windowSplashScreenAnimatedIcon=@drawable/ic_launcher_foreground`），不加 noHistory。
- logo 资源：`app/shared/src/main/res/drawable/ic_launcher_foreground.xml`（粉色 B 站 vector），三个 splash 主题都配了它，配置本身没丢。
- 验证：`:app:tv:compileDebugKotlin`/`:app:mobile:compileDebugKotlin`/`:app:compileDefaultDebugKotlin` → BUILD SUCCESSFUL；`:app:assembleDefaultDebug` 成功；合并清单确认 SplashActivity=Theme.BV.Splash、MainActivity=普通主题。
- 备注：用户中途曾要求"放弃所有修改"（已 git restore 回退到 f7037cb4 基线），随后按此思路重新实现。`libs` 子模块脏状态（.gitignore/README.md）非本次改动，未动。

## Splash logo 方案 v2（Compose 开屏兜底）
- v1（纯 setKeepOnScreenCondition + ActivityLifecycleCallbacks）在 tv 模拟器上仍无 logo。根因推测：API < 31 上 compat splash 画在 SplashActivity 自己窗口，而 v1 无 setContent，窗口不绘制第一帧，splash 视图没机会显示；MainActivity 很快盖住。
- v2 方案：SplashActivity 同时 (a) installSplashScreen + setKeepOnScreenCondition 撑住系统/compat splash，(b) setContent 显示 Compose 开屏界面（Box + 暗色背景 #1A1A1A + Image(ic_launcher_foreground, 160dp)）。setContent 让窗口有内容可绘制，确保 API < 31 上 compat splash 能显示，也作为系统 splash 未触发时的兜底。MainActivity onResumed 后 finish。
- compose 依赖可用性：shared/build.gradle.kts 用 `api` 暴露全部 compose 依赖（androidx.compose.ui/material3/activity.compose 等），app 主模块经 `implementation(project(":app:shared"))` 传递获得，故 app/src/main 可直接 setContent。
- 验证：`:app:compileDefaultDebugKotlin` + `:app:assembleDefaultDebug` 均 BUILD SUCCESSFUL。
- 待用户确认：tv 模拟器 API 版本（`adb shell getprop ro.build.version.sdk`）、是否安装的是刚打包的 dev.oaktech.bv.debug 包。

## Splash logo 方案 v3（延迟转发，API 28 定位）
- 用户确认 tv 模拟器 API = 28（Android 9），走 compat splash 路径。
- v2（setContent + Compose 开屏）在 API 28 上仍无 logo。根因：compat splash 画在 SplashActivity 自己窗口，需窗口绘制第一帧后才显示；但 v2 在 onCreate 里立即 startActivity(MainActivity)，MainActivity 启动太快，在 SplashActivity 窗口 onPreDraw 之前就把它盖住，splash 视图没机会显示。
