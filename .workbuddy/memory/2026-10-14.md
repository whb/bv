## 构建失败排查：libs 子模块未初始化
- 现象：`:player:core:compileDebugJavaWithJavac` 失败，报 "No matching variant of project :libs:ffmpegDecoder ... No variants exist"。
- 根因：`libs` 是 git submodule（.gitmodules 指向 https://github.com/aaa1115910/bv-libs.git），`git submodule status` 前缀为 `-`（未检出），磁盘上 libs/ 为空。settings.gradle.kts:31-33 include 了 :libs:av1Decoder / :libs:ffmpegDecoder / :libs:libVLC，但模块不存在 → Gradle 解析不到变体。
- 修复：`git submodule update --init --recursive`，checkout 5e300a5，libs/ 下 av1Decoder/ffmpegDecoder/libVLC/media3Container 均已就位。
- 教训：clone 仓库后必须先初始化子模块，否则 player 模块无法编译。

## TV 设备从 LAUNCHER 入口自动转发到 TV 界面（方案A）
- 问题：融合包同时注册 LAUNCHER(mobile) 与 LEANBACK_LAUNCHER(tv)。非原生 TV 启动器/侧载/应用列表只认 LAUNCHER，导致在 TV 上打开的是 mobile 界面。
- 改动：`app/mobile/.../mobile/activities/MainActivity.kt`
  - 新增 imports：ComponentName / Intent / PackageManager。
  - onCreate 在 setContent 前检测 `packageManager.hasSystemFeature(FEATURE_LEANBACK)`；若是 TV 设备，用 ComponentName 显式启动 `dev.aaa1115910.bv.tv.activities.MainActivity` 并 finish() 自身（return，不渲染 mobile UI）。
  - 新增私有函数 `isTvDevice()`。
- 设计点：用 ComponentName 字符串启动，避免 mobile 模块反向依赖 tv 模块；包名用 `packageName`（兼容 debug 的 .debug 后缀）。手机设备 FEATURE_LEANBACK=false，不触发转发，行为不变。
- 未验证：沙箱无 Android SDK，未能实跑编译；改动经静态核对。
