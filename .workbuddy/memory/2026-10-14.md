## 再次修复 up 主视频列表（第一轮"主线程 addAll"未解决）

  3. 首次 `getSpaceVideos` `runCatching` 失败则 `delay(500)` 重试一次；

## 三修 up 主视频列表（前两轮未解决，定位到 WBI 签名层真因）
- 用户反馈仍未修复："有时正确显示，有时什么也不显示，需返回重进"。并要求：确实没有视频时提示"没有视频"，不要白屏。
- 真因：关注列表用非 WBI 接口（故列表总能加载）；up 主视频走 `/x/space/wbi/arc/search`（WBI 签名接口）。`BiliHttpApi` 的 wbi keys 在 init 里异步预热，且 `updateWbi()` 有两个硬伤：
  1. 失败被 `runCatching{}.onFailure{仅打印}` 静默吞掉 → keys 拿不到时 `encWbi()` 的 `require` 直接抛异常 → 请求整体失败；VM 层"重试一次"常落在同一空 keys 窗口，故未修住；
  2. `needToUpdate` 比较符写反（`<` 应为 `>`）→ keys 陈旧后永不刷新，B 站轮换 key 后签名必 -403。
  另外原 UI 无空状态：加载完成但列表为空时 LazyColumn 白屏。
- 修复（4 处）：
  1. `BiliHttpApi.updateWbi()`：修反的比较符；加 `wbiUpdateMutex` 去重并发刷新；nav 失败带退避重试 3 次（300/600/900ms）；返回 Boolean。
  2. `ApiSign.encWbi()`：改为无条件调用自守护的 `updateWbi()`（内部判断新鲜度立即返回），同时覆盖 keys 为 null 与陈旧两种情况。
  3. `UserSpaceViewModel`：重试改 3 次带退避（400/800/1200ms）；CancellationException 向上抛；**已关注 UP 首页返回空时多甄别重试一次**（风控抖动返回空列表而非报错）；新增 `loading`/`loadFailed`/`loadedOnce` 状态；TV 端成员（tvSpaceVideos/noMore/update()）全部保留。
  4. `UserSpaceScreen.kt`（mobile）：三态 UI——加载中 / "没有视频"（`loadedOnce && 空`）/ 加载失败+重试按钮。新增字符串 `user_space_loading`、`user_space_no_video`、`user_space_load_failed`、`user_space_retry`。
