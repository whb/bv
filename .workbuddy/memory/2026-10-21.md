## 扫码登录"成功但显示二维码已过期"修复
- 现象：TV/mobile 扫码登录，账号已登录成功，画面却显示"二维码已过期"。
- 根因：`AppQrLoginViewModel` 用 `timeTask(1000,1000,...)`（无条件周期 Timer）轮询，poll 网络耗时 >1s 时请求重叠；成功的 poll 会消费 auth_code，使在飞的旧 poll 返回 86038（过期），`state = qrLoginResult.state` 无条件写入 → 晚到的 Expired 覆盖 Success。
- 修复（`app/shared/.../viewmodel/login/AppQrLoginViewModel.kt`，TV/mobile 共用）：① 周期 Timer 换串行协程循环（`while(true){ delay(1000); checkLoginResult() }`，`checkJob: Job` 替代 `java.util.Timer`）；② `@Volatile terminalReached` 终态保护，Success/Expired 处理后丢弃后续结果，`requestQRCode()` 重置。
- 验证：shared/tv/mobile compileDebugKotlin BUILD SUCCESSFUL。

## 扫码登录回归修复（同一提交 d440fe50 引入的新 bug）
- 现象：扫码登录"显示成功，实际没有登录成功"（界面 state=Success，但账号未真正落盘）。
- 根因：d440fe50 在 `checkLoginResult()` 的 Success/Expired 分支里调用 `checkJob?.cancel()`，而 `checkJob` 正是正在执行该函数的协程本身 → 协程自取消，协作式取消在下一个挂起点抛 `CancellationException`，紧接着的 `userRepository.addUser(authData)` 被中断（未执行 Room 写入 / `saveToPrefs` / 仓库重初始化）。但 `state` 已在分支前被设为 `QrLoginState.Success`，故"显示成功、实际未登录"。
- 修复：① `while(true)` → `while(!terminalReached)`，用终态标志自然退出循环；② 删除 Success/Expired 分支里的 `checkJob?.cancel()`（自取消），仅置 `terminalReached=true`；③ Success 分支先完整执行 `addUser` 再置终态，确保登录态落盘。`requestQRCode()`、`cancelCheckLoginResultTimer()` 中的外部 `checkJob?.cancel()` 保留（安全）。
- 验证限制：本沙箱 KSP（`:symbols:kspKotlin`）访问 raw.githubusercontent.com 超时，无法在此环境完成 full compile；改动已逐行人工复核。须用户在本地 `assemble` 打包上电视测验证。

## Zed Kotlin LSP 无法导入 Gradle 项目（IDE 工具侧问题，非项目 bug）
- 现象：Zed 的 kotlin-lsp（`kotlin-lsp-263.6379.0`，内置 JBR Java 25）报 `Unable to import a Gradle project: BuildActionFailureException`。
- 根因（读 `idea-system*/system/log/intellij-server.log` 的 IMPORT ERR 段）：JetBrains LSP 的 Android 模型构建器 `com.jetbrains.ls.imports.gradle.model.builder.android.AndroidSourceSets` 在导入时解析 `:player` 的 androidTest source set，提前读取了 `:player:generateDebugAndroidTestBuildConfig` 任务的输出 Provider，Gradle 拒绝（`InvalidUserCodeException: Querying the mapped value of provider(...generateDebugAndroidTestBuildConfig...) before task ... has completed is not supported`）。整个异常栈都是 JetBrains LSP 代码，命令行 `assemble` 正常 → IDE 工具侧兼容性问题。
- 环境版本：AGP 8.11.1 / Kotlin 2.2.0 / Gradle 8.14.5 / KSP 2.2.0-2.0.2。（曾怀疑 JDK25、KSP 联网，均排除——daemon 正常启动、依赖解析全 succeeded，失败仅发生在模型构建阶段。）
- 影响范围：4 个模块 `buildConfig=true`（`:player`、`:player:shared`、`:app:shared`、`:utils`），导入遇首个即中止，故单改某模块无效，是 LSP 系统性问题。
- 结论/处置：升级 Zed 的 Kotlin LSP 扩展到最新版（JetBrains 已重写 Android source set 模型构建）。**不要**为规避而关 `:player` 的 buildConfig——`BuildConfig.libVLCVersion` 被 `app/tv/.../LibVLCDownloaderDialog.kt`（`import dev.oaktech.bv.player.BuildConfig`）引用，关了编译失败，且对其他模块也没用。项目构建/提交/打包不依赖 Zed 的 Gradle 导入，仅影响编辑器内索引/补全。
- 同日追问「升级 AGP 能否解决该 LSP 导入报错」→ 查证结论：**不能指望**。① 该异常是 Gradle 核心 Provider 校验（Gradle 7.0 起即为硬错误，6.x 为 deprecation），触发点是 LSP 模型构建器提前查询任务输出 Provider；任何 AGP（7.x~9.x）都会把 androidTest 变体的 BuildConfig 生成目录挂在 `generateDebugAndroidTestBuildConfig` 任务输出上，LSP 提前查即抛，与 AGP 版本无关；② kotlin-lsp 官方文档明确 Android Gradle 支持仍是 experimental（项目整体 Alpha），修复责任在 JetBrains；③ 无任何 changelog/issue 表明某 AGP 版本修过此 LSP 报错。AGP 版本线（2026-10 时点）：8.x 最终版 8.13.2（2025-09，需 Gradle 8.13+/JDK17）；9.0.1（2026-01）/9.1.1、9.2.0（2026-04，需 Gradle 9.1+/9.3+，强制内置 Kotlin 2.2.10，新 DSL 独有、旧 Variant API 全移除）。9.x 迁移成本（Gradle 9 + KGP + 第三方插件 + 全量重验，且本沙箱 KSP 断网无法编译验证）与一个编辑器导入错误完全不成比例；8.11.1→8.13.2 小升级修的是 R8/AAR/KMP 问题，同样不动此报错。建议：等 ILS 周更 / 报 issue / 切 fwcd kotlin-language-server；升级 AGP 只作为独立的版本跟进决策，勿以修 LSP 报错为目的。
- 决定性复核（同日）：zed-extensions/kotlin 扩展 **v0.3.4 已是最新**（main 分支同版本），且它**动态下载最新 ILS**——`src/language_servers/kotlin_lsp.rs` 的 `get_release()` 每次拉 `Kotlin/kotlin-lsp` 的 `RELEASES.md` 取首个 `### vXXX`，LSP 启动时下载到 `work/kotlin/kotlin-lsp-<ver>` 并 `remove_outdated_versions` 清旧版。RELEASES.md 当前最新 = **263.6379.0 = 已安装版本**，故**无更新可拉、"更新"是空操作，不会修复**该 AGP 8.11 导入 bug（未见于任何 changelog 已修复项）。强制重拉：删 `%LOCALAPPDATA%\Zed\extensions\work\kotlin\kotlin-lsp-*` 再 reload。ILS 每周从 master 出新 build，扩展会自动跟上。备选：切回默认 `kotlin-language-server`（fwcd，走 Gradle Tooling API，不经 `com.jetbrains.ls.imports`）；或向 `Kotlin/kotlin-lsp` 提 issue（附 intellij-server.log 的 IMPORT ERR 段）。Zed CLI 无扩展子命令，扩展管理仅 GUI（Ctrl+Shift+X）。注：用户/项目 settings.json 均无 kotlin-lsp 覆盖，但 JetBrains ILS 却在跑——开启来源存于 Zed 工作区 DB，需在 Zed 内确认 Kotlin 语言服务器选择。
