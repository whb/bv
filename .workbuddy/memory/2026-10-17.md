## TV 搜索功能：模拟器正常、电视操作两下闪退 调查
- 现象：TV 版搜索功能在模拟器正常，真实电视上用遥控器"操作两下"就闪退（crash）。
- 关键判断：模拟器用鼠标（不触发 DPad 焦点导航），电视用遥控器方向键（触发 Compose 焦点导航逻辑）。故为 **TV 焦点导航（DPad）专属崩溃**，与逻辑无关的环境差异。高概率区域：
  1. 结果页 `SearchResultScreen.kt`：`LazyVerticalGrid` 每个 item `onFocus = { currentIndex = index }` → `LaunchedEffect(currentIndex)` → `loadMore`；`Tab` 的 `onFocus = { searchType = type }` 改变 `rowSize` 导致 `LazyVerticalGrid` 列数重建。焦点驱动双向绑定，TV 上极易焦点跳动/重组风暴/索引异常。
  2. 输入界面 `SearchInputScreen.kt`：`Row + horizontalScroll + 三个 focusGroup`（SearchInput/SearchHotwords/SearchHistory）手动焦点架构，TV 遥控器导航下焦点易迷失错乱。
- 已排除：网络层（`updateSuggests`/`loadMore` 均有 `runCatching` 兜底）、`swapListWithMainContext`（切主线程串行 swap，线程安全）。
- 已修确定隐患：`SearchKeyword.kt` 每次重组 `ImageLoader.Builder(...).build()` 新建带 OkHttp 线程池的 ImageLoader（热搜词 LazyColumn 滚动时反复创建，TV 高危），改为用 Coil 默认全局单例，并清理 `Build`/`coil.decode`/`coil.size`/`coil.ImageLoader` 等未用 import。
- 待办：需用户在电视上抓 logcat 崩溃堆栈精确定位（adb connect 电视IP:5555 → adb logcat -b crash；复现后复制 "FATAL EXCEPTION" 堆栈贴回）。未做大规模猜测性改代码，避免引入新问题。
- 代码路径：输入 `app/tv/.../screens/search/SearchInputScreen.kt`、`component/search/{SearchKeyword,SoftKeyboard}.kt`、`activities/search/SearchInputActivity.kt`；结果 `tv/screens/search/SearchResultScreen.kt` + `shared/.../viewmodel/search/{SearchInputViewModel,SearchResultViewModel}.kt`。

## 播放组件升级：Media3 1.8.0-rc01 → 1.11.1，libvlc-all 3.6.0-eap5 → 3.7.6
- 改：`gradle/androidx.versions.toml:15` `media3 = "1.11.1"`（原 1.8.0-rc01，RC 预览版升稳定版）；`gradle/libs.versions.toml:28` `vlc = "3.7.6"`（原 3.6.0-eap5，EAP 升稳定主线）。
- 验证：`./gradlew :app:compileDefaultDebugKotlin -PdualAbi=true` → **BUILD SUCCESSFUL**（27s，EXIT=0）。player:core/player:mobile 因 media3 版本变更重编译且通过 → media3 1.11.1 API 兼容；app:aarMetadata 通过 → libvlc-all 3.7.6 联网解析下载成功。仅余历史 warning（namespace 重复、ksp db 参数），与本次无关。
- **libVLCVersion 常量核对结论（关键）**：`AppConfiguration.libVLCVersion = "3.0.18"` 经 `BuildConfig.libVLCVersion` 传入 `VlcLibsApi.getRelease()`（`LibVLCDownloaderDialog.kt:68`），用于**运行时从 `whb/bv-libs` 下载 VLC 原生 .so**（APK 经 `app/build.gradle.kts` exclude 剥离 .so，靠运行期补齐）。它代表 `whb/bv-libs` 的 release tag，**与 libvlc-all 的 Maven 版本号是两回事**。原值 3.0.18 与旧 maven 3.6.0-eap5 本就不一致 → 作者故意解耦两套版本。**未盲改该常量**（若改 3.7.6 会导致运行时去 bv-libs 找 3.7.6 tag，大概率下载失败）。
- 运行时风险提醒（需用户在真机验证）：maven Java 绑定升到 3.7.6，而运行期下载的 .so 仍由 libVLCVersion(3.0.18) 决定。若要严格匹配，需在 `whb/bv-libs` 发布基于对应 libvlc 核心的 .so 并把 libVLCVersion 指向该 tag。用户需确认 whb/bv-libs 实际发布的 tag。
- 本地三层 aar（不可 Maven 升级）：`libs/{av1Decoder,ffmpegDecoder,libVLC}/*.aar` 来自 whb/bv-libs 预编译，升级需重新拉取/编译覆盖 libs/ 文件。

## 尝试弃用本地 libs 子模块，改用官方 Maven 版本
- 用户要求：放弃自己改写的 libs，直接用 av1Decoder/ffmpegDecoder/libVLC/media3Container 官方较新版本。
- 关键发现（读 libs/README.md + aar manifest package）：四个本地 aar 的包名分别是 `androidx.media3.decoder.av1` / `androidx.media3.decoder.ffmpeg` / `org.videolan` / `androidx.media3.container`；且 README 写明 av1 打包自 Media3 1.0.0-beta03、ffmpeg 自 1.5.0、libVLC 自 VLC-Android 3.6.0-ep05（**修改过**：去 UserAgent 末尾 `LibVLC/xxx`、改 native lib 加载路径）、media3Container 自某 Media3 commit。是"打包过"而非纯 stock。
- 更重要：全仓库 grep 发现 **4 个里只有 ffmpegDecoder 真正被依赖**（`player/core/build.gradle.kts` 一处 `implementation(project(":libs:ffmpegDecoder"))`，且代码用 `DefaultRenderersFactory EXTENSION_RENDERER_MODE_ON` 经类路径自动发现 FFmpegAudioRenderer，故无显式 import）；av1Decoder/libVLC/media3Container 在 .gradle.kts 里**无 implementation 引用**（只在 settings include，且 media3Container 连 include 都没有，是 dangling submodule）。当前代码 player 模块全是 Media3/ExoPlayer，无 VLC MediaPlayer 实现，VLC 仅"设置+运行时下载器"。**libvlc-all 3.7.6 已在 libs.versions.toml 定义（`vlc-android-all`）但此前无人引用。**
- 编译验证结论（`./gradlew :app:compileDefaultDebugKotlin -PdualAbi=true`）：
  - ✅ `androidx.media3:media3-container:1.11.1` 官方存在 → 替换本地 media3Container 成功。
  - ✅ `org.videolan.android:libvlc-all:3.7.6` 官方存在 → 替换本地 libVLC 成功（`player/core` 加 `implementation(libs.vlc.android.all)`）。
  - ❌ `androidx.media3:media3-decoder-av1:1.11.1` 与 `androidx.media3:media3-decoder-ffmpeg:1.11.1` **Google/阿里云/Maven Central/JitPack 均无发布**（已逐一搜 dl.google.com、maven.aliyun、repo.maven.apache.org、jitpack、repo1.maven.org、androidx.dev 全部 404）。即 Google **不发布**这两个解码器到 Maven，只能从 Media3 源码树本地编译——这正是 bv 当初打包成 aar 的原因。故 av1/ffmpeg **无法用官方 Maven 替换**，还原回本地工程依赖。
- 最终落地改动：
  - `gradle/androidx.versions.toml`：新增 `media3-container`（version.ref=media3）。**未加** decoder-av1/ffmpeg（官方不存在）。
  - `player/core/build.gradle.kts`：`implementation(androidx.media3.container)` + `implementation(project(":libs:ffmpegDecoder"))`(保留本地) + `implementation(libs.vlc.android.all)`(官方)；删除原 `implementation(project(":libs:ffmpegDecoder"))` 的"仅本地"写法已改为含官方 container+vlc。
  - `settings.gradle.kts`：删除 `include(":libs:libVLC")`（改用官方 libvlc-all）；保留 `include(":libs:av1Decoder")` 与 `include(":libs:ffmpegDecoder")`（官方无发布，不能弃）。
  - `app/proguard-rules.pro:97-98` 已有 `-keep class org.videolan.libvlc.** { *; }`，正好适配官方 libvlc-all。
- 编译环境插曲：回退后首次重编报 `player/shared/.../classes.jar 另一个程序正在使用此文件`（文件锁）→ 属历史遗留 daemon 锁 build 目录；`./gradlew --stop` + `pkill GradleDaemon/KotlinCompileDaemon` 清理后重编 → BUILD SUCCESSFUL（2m15s，EXIT=0）。教训：连续两次 gradle 后台编译易残留锁，重编前先 `--stop`。
- 结论汇报用户：4 个里 **2 个可官方替换（media3Container、libVLC），2 个不可（av1、ffmpeg 官方不发布）**。libVLC 用官方后 UserAgent 末尾 `LibVLC/3.7.6` 会恢复（原修改版去掉了）、native 加载路径改回标准 jniLibs；Lite 构建仍按 `app/build.gradle.kts` strip 其 .so 且运行时下载器仍下旧 modified .so（与官方绑定不匹配，VLC 播放功能本就无实现，影响有限）。
