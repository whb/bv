## TV 抽屉动态宽度机制 + 之前错乱根因诊断
- 机制：tv.material3 `NavigationDrawer` 有 Open/Closed 两态，组件内部按 `DrawerValue` 在 expanded（图标+文字，宽）与 collapsed（仅图标，窄）之间做宽度动画；`DrawerContent` 里 `NavigationDrawerItem` 宽度跟随 drawer sheet 宽度（item 自身未设固定宽，label Text 始终渲染，靠 sheet 裁剪实现折叠只显图标）。即"按钮动态大小"由库内置状态驱动，非 DrawerContent 控制。
- 官方控制宽度方法（developer.android.com TV NavigationDrawer 文档）："To limit the width of the drawer in the open or closed state, wrap the content in a box with the required width." —— 在 `drawerContent` 内部根容器加固定宽度，而非在 `NavigationDrawer` 的 `modifier` 上加 width。
- 错乱根因：此前把 `.width(128.dp)` 加在 `NavigationDrawer(modifier = modifier.width(128.dp), ...)`（外部 modifier），干扰 tv.material3 内部 sheet 测量/动画 → 画面错乱。用户已回退。
- 正确做法：仅给 `DrawerContent` 根 Column 加 `widthIn(max = 120.dp)`（限最大、保留动画）或 `width(128.dp)`（固定宽度、动画减弱）；**不要**动 `NavigationDrawer` 的 modifier。回退后暂未重加。
- 进阶（可选）：`drawerContent` lambda 签名 `NavigationDrawerScope.(DrawerValue) -> Unit`，可接收 DrawerValue 在 Open 渲染 label、Closed 只图标，做更可控显隐而非靠裁剪；当前 `MainScreen` 调用 `{ DrawerContent(...) }` 忽略了该参数。

## 修复"栏压窄后 6 个按钮显示不正确"
- 现象：给 `DrawerContent` 根 Column 加 `widthIn(max = 120.dp)` 后，左侧栏总宽确实变窄，但内部 6 个 `NavigationDrawerItem`（User + Search/Home/UGC/PGC 在 LazyColumn + Settings）渲染错位：item 默认 `wrapContent` 宽度、文字未限单行 → 在 120dp 栏内左对齐留白、或文字挤换行/裁切（"点击登录"/用户名尤甚）。
- 根因：tv.material3 抽屉宽度是 wrap-content，栏宽=内容宽，缩栏必然压缩按钮可用空间；item 未 `fillMaxWidth`、Text 未 `maxLines=1` 导致适配异常。
- 修复（仅 `DrawerContent.kt`，不动 `NavigationDrawer` 的 modifier）：
  - 3 处 `NavigationDrawerItem` 的 `modifier` 加 `.fillMaxWidth()`（User/Settings 由 `Modifier` 改为 `Modifier.fillMaxWidth()`；LazyColumn 项链式追加 `.fillMaxWidth()`），让按钮铺满收窄后的栏宽、消除留白/错位。
  - 4 个列表项 + Settings 的 `Text` 加 `maxLines = 1` + `overflow = TextOverflow.Ellipsis`（User 项本身已有 `basicMarquee`+`maxLines=1`，保留）；新增 `import androidx.compose.ui.text.style.TextOverflow`。
  - 根 Column 仍保留 `widthIn(max = 120.dp)`，展开/折叠动画不变。
- 说明：栏宽=内容宽，无法"只缩栏不改按钮"——按钮必随栏适配；本改法让适配优雅（铺满+截断省略号），而非错位/换行。120 这个值可按真机观感调（含"点击登录"4 字约需 128dp 才能不截断，调大即不省略）。
- 未验证：沙箱无 SDK。需本机 `:app:assembleDefaultDebug` 真机/模拟器确认 6 按钮铺满、文字不换行。
- 编译报错修复：本机 `:app:tv:compileDebugKotlin` 报 `DrawerContent.kt:97/159/179 Unresolved reference 'fillMaxWidth'`——漏加 `import androidx.compose.foundation.layout.fillMaxWidth`（与之前漏 `width` 同类）。已补，3 处引用消除。教训：凡用 Compose modifier 扩展函数（fillMaxWidth/width/widthIn 等）必须确认对应 layout import 已存在。

## 根因确认：tv.material3 NavigationDrawerItem 宽度不可经 Modifier/Column 改变
- 直接读 `androidx.tv:tv-material:1.1.0-alpha01` 源码（sources jar 在 gradle 缓存）确认机制：
  - `NavigationDrawerItem.kt` 内部用 `modifier.layout { ... }` 把 item 宽度**强制**为 `animatedWidth`（`constraints.copy(minWidth=width, maxWidth=width, ...)`），传入的任何 `Modifier`（含 `fillMaxWidth`/`width`）都被覆盖。
  - `animatedWidth` 来自 `NavigationDrawerItemDefaults` 对象内写死的 `val`：`ExpandedDrawerItemWidth = 256.dp`（抽屉展开/聚焦）、`CollapsedDrawerItemWidth = 56.dp`（收起）。该 `val` 无参数可传、不可覆盖。
  - `hasFocus` 来自 `NavigationDrawerScope.hasFocus`（"抽屉内任一 item 是否聚焦"），由 `NavigationDrawer` 在 Open+聚焦时置 true → 所有 item 同时 256；Closed → 同时 56。即"栏展开变宽"= 整个抽屉 56→256。
- 结论：6 个按钮最大宽度**无法**靠 Modifier 或外层 Column `widthIn` 改变；之前 `widthIn(max=120)` + `fillMaxWidth` 全部无效（120 只缩容器、256 按钮溢出/裁切，故"按钮宽度依然不对"）。唯一改法：fork `NavigationDrawerItem` 源码本地改这两个常量。
