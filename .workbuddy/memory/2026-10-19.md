## TV 入口 Activity 在雷鸟/TCL 实体电视选错
- 现象：AVD Android TV 模拟器正确进 `tv.activities.MainActivity`；雷鸟/TCL 实体电视却进 `mobile.activities.MainActivity`。
- 根因：`app` 单 APK 同编 `:app:mobile` 与 `:app:tv`，两个 MainActivity 共存（mobile=LAUNCHER，tv=LEANBACK_LAUNCHER）。`mobile.MainActivity.onCreate` 有 `isTvDevice()` 兜底跳 tv，但 `isTvDevice()` 仅判 `FEATURE_LEANBACK`。
- 模拟器(AVD)用 Leanback 启动器，匹配 LEANBACK_LAUNCHER → 直接进 tv。**雷鸟/TCL 关键事实（已实测）**：`pm list features` 含 `android.software.leanback` + `android.software.leanback_only`，故 `isTvDevice()`=true → 兜底跳转**成功** → 最终显示 tv UI（用户已确认）。它仍"先经 mobile 再跳 tv"的原因是：**启动器选型看的是它查询的 intent category，与设备是否声明 leanback 特征无关**——雷鸟自研桌面用 `CATEGORY_LAUNCHER` 解析（只匹配 mobile 的 LAUNCHER），而不是 LEANBACK_LAUNCHER。即"经过 mobile"是预期行为，非 bug。
- 排查（真机 adb，已验证有效）：`resolve-activity -c LAUNCHER dev.oaktech.bv` → 解析到 mobile.MainActivity（证实桌面走 LAUNCHER）；`pm list features | Select-String leanback` → 含 leanback+leanback_only（证实 isTvDevice 会返回 true）；`dumpsys activity activities | Select-String ResumedActivity` → 确认最终前台是 tv.MainActivity（跳转成功）。
- 修复方向（可选）：当前 isTvDevice 已能识别该设备，补强检测对此设备无必要。"先经 mobile 再跳 tv"若想消除，标准做法是改单一 dispatcher Activity 同时挂 LAUNCHER+LEANBACK_LAUNCHER，运行时按 isTvDevice 转发；其余保持不变。

## lite release 雷鸟闪退根因定位与修复（22:00-22:30）
- crash3.log 抓到真实堆栈：`IllegalStateException: LayoutNode should be attached to an owner`（draw 阶段），两次重复。
- 用 `cmdline-tools/latest/bin/retrace.bat` + `app/build/outputs/mapping/liteR8Test/mapping.txt` 反混淆：`requireOwner ← NodeCoordinator.draw ← LayoutModifierNodeCoordinator.performDraw`。
- 对照 Google Issue #425120571：Compose 1.8 + **仅 Android 9** + R8，同堆栈。
- 根因铁证：Compose 1.8 把 `ViewLayerContainer` 从 `androidx.compose.ui.platform`（ui artifact）挪到 `androidx.compose.ui.graphics.layer.view`（ui-graphics），但 ui 的 consumer proguard 规则仍 keep 旧包名（失效），ui-graphics 无规则。R8 因 android.jar stub 不含 framework hidden API `ViewGroup.dispatchGetDisplayList()`，判定其无调用者而**删除**该方法 → Android 9（API<29 才走 dispatchGetDisplayList 分发 display list）分发失效 → draw 访问已 detach 的 LayoutNode → ISE。
- dex 字符串验证：r8Test APK 3 个 dex 全无 `dispatchGetDisplayList`；debug APK classes4.dex 有 → 解释"debug 稳、release 崩"。
- jerboa（Lemmy 客户端）同款修复 PR #1871：只加一条 proguard keep。
- **修复**：`app/proguard-rules.pro` 加 `-keepclassmembers class androidx.compose.ui.graphics.layer.view.ViewLayerContainer { protected void dispatchGetDisplayList(); }`（+旧包名兜底），随后重新打 liteR8Test universal 包待用户复测。
- 备注：compose 1.9.0-beta02 的 ui/ui-graphics consumer rules 与 1.8.3 完全相同（仍未修），升级 compose 版本不能解决，须项目侧 keep。
